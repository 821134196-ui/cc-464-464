# 试驾车预约与车况交接平台

汽车门店试驾车的预约审核、出车放行、路线计时、回车对照、违章留观与事故复核一体化工作台。
**零第三方依赖**：仅使用 Node.js 22 内置的 `node:sqlite`、`node:http` 与原生前端。所有人员、车辆、客户、驾照与付款信息均为**虚构模拟数据**。

## 一条命令启动

```bash
npm start
# → http://localhost:5173
```

首次启动自动建库、写入种子数据（含冲突与事故样例）并开启进程内定时任务。重置演示数据：

```bash
npm run reset   # 删除 data/ 后重建种子
npm test        # 21 项规则测试
```

- 数据库：`data/testdrive.db`（SQLite，含车况版本链）
- 车身照片：`data/photos/<预约号>/<out|return>/<front|rear|left|right>.svg`
- 环境变量：`TD_PORT`（默认 5173）、`TD_GRACE_MIN`（迟到宽限 15）、`TD_LOW_FUEL`（低油阈值 15%）、`TD_WATCH_MIN`（留观时长，默认 3 天）、`TD_TICK_MS`（定时任务间隔 10s）

## 八个工作台页面

| 页面 | 能力 |
| --- | --- |
| 车辆状态板 | 车辆**按车型分组**为紧凑卡片：里程（等宽字体）、油量条、异常标注，点击查看车况版本链与加油 |
| 车型日历 | 时间轴**同时展示车辆泳道与销售顾问泳道**，可按日期切换，跨日订单打标 |
| 预约审核 | 新建申请、冲突预检、通过即**锁定车辆与顾问**并模拟扣押金、驳回、换车、跨日审批 |
| 出车清单 | 逐项核对证件（发车瞬间调驾照适配器）、出车里程、油量、**四方位照片**；低油量/迟到/异常拦截 |
| 路线计时 | 在外车辆实时计时，超过计划时间红色倒计时，回店超时需主管确认并生成超时审批 |
| 回车对照 | 沿车身**前/后/左/右四个固定位置**拍摄，新旧照片**拖动分隔线**对比；补录结束里程与新损伤 |
| 违章留观 | 留观倒计时，到期系统自动结束；留观结束 **且** 清洁完成车辆才恢复可约 |
| 事故复核 | 事故/故障报备即锁车；**结论由主管确认，普通销售不能清除车况异常** |

## 核心业务规则

- **时段互斥**：同一车辆、同一顾问均不能存在重叠的生效预约；审核时双重检测。
- **同时发车只接受一次**：开放出车单在车辆维度有部分唯一索引兜底（两名顾问双击/并发只成功一条），顾问维度也禁止同时带两台车。
- **预约通过即锁定**车辆与销售顾问；模拟支付失败则不锁定。
- **临时换车**：同车型顾问可直接调换；**换车型必须主管的换车型审批**；异常/在途车辆不能调入。
- **跨日试驾必须创建单独审批记录**后才能审核通过。
- **出车前**：驾照适配器实时核验（尾号 `X` 样本判无效）、里程车机读取、油量不得低于阈值、四方位照片齐全、未超迟到宽限。
- **回店里程连续**：结束里程不得小于出车里程与台账里程，否则拒绝回车。
- **新损伤**：勾选方位即生成事故复核单、车辆 `incident_locked` 锁车，待主管确认。
- **流程闭环**：回店 → 违章留观 + 清洁待办；两项均完成且无未结事故，车辆才重新 `available`。
- **进程内任务**：每 10 秒扫描——超宽限未发车自动 `released_late` 并释放车辆；留观到期系统自动结束。
- **数据权限**：销售只能操作分配给自己的预约；审核、跨日/换车型审批、事故确认与异常清除、提前结束留观均需主管。

## 异常情形如何处理

| 情形 | 处理 |
| --- | --- |
| 客户迟到 | 超过 15 分钟宽限未发车，定时任务自动释放预约与车辆 |
| 临时换车型 | 普通顾问被拒；主管补「换车型」审批后可调入 |
| 证件无效 | 发车瞬间驾照适配器返回无效，阻止发车（客户 C-1007 尾号 X 样本） |
| 路线超时 | 回店时自动生成「路线超时」审批，需主管身份提交 |
| 低油量 | 低于 15% 禁止出车，先在状态板/清单登记加油（生成车况版本） |
| 事故报备 | 任一员工可报备，立即锁车；主管确认结论、整改后清除异常 |
| 照片差异 | 四方位固定位拖动对比，勾选新损伤方位并填写说明才生成事故单 |
| 车辆故障 | 与事故同一复核流（TD202 为待确认故障样例） |

## 种子样例（启动即可演示）

- `TD-TODAY-0006/0007`：同车时段重叠（审核 0006 后 0007 被车辆冲突拦截）
- `TD-TODAY-0008`：顾问林澈与 0001 时段重叠（车辆空闲，仅拦顾问冲突）
- `TD-TODAY-0002`：跨日试驾，无单独审批不能通过
- `TD-TODAY-0003`：沈眉已出车，路线已超时
- `TD-TODAY-0004`：留观到期（首个定时 tick 自动结束）、清洁待完成
- `TD-TODAY-0005`：迟到超宽限（首个定时 tick 自动释放）
- `TD-TODAY-0009`：客户驾照尾号 X，发车被适配器拦截
- `TD-TODAY-0010`：左后门事故，主管已确认待清除（普通销售清不掉）
- `苏A·TD202`：车辆故障报备待主管确认

## 架构

```
src/
  schema.sql     表结构（预约/出车/留观/清洁/事故/车况版本/审批/付款/审计）
  db.js          node:sqlite 连接、事务、目录
  store.js       数据访问
  adapters.js    模拟适配器：驾照核验 / 车机里程 / 付款
  services.js    全部业务规则 + 进程内调度器
  photos.js      车身照片本地落盘与目录穿越防护
  car-art.js     四方位矢量车身图生成（含新损伤标注）
  seed.js        虚构种子数据
  server.js      HTTP API + 静态资源
public/          原生 SPA（状态板/日历/审核/出车/计时/回车/留观/事故）
test/            node:test 规则与 HTTP 全流程测试
```

车况每次基线、出车、回车、事故、加油、异常清除都写入 `vehicle_condition_versions`，里程连续可逐版追溯。
