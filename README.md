# 试驾车预约与车况交接平台

汽车门店试驾车的预约审核、出车交接、路线计时、回车对照、违章留观与事故复核一体化工作台。
**人员与车辆数据均为虚构**，外部能力（驾照核验、车机里程/油量、押金付款）由本地模拟适配器提供。

零第三方依赖：仅使用 Node.js ≥ 22.5 内置的 `node:sqlite`、HTTP 服务与原生前端（无构建步骤）。

---

## 一条命令启动

```bash
npm start
# 等价于 node --no-warnings src/server.js
```

打开 http://localhost:5173 。首次启动自动建库、写入带冲突与事故样例的虚构数据，并在本地生成四方位车身占位照片。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `TD_PORT` | `5173` | 监听端口 |
| `TD_RESET` | `0` | 为 `1` 时启动先清空数据库（或加 `--reset`） |
| `TD_DB_PATH` | `data/app.db` | SQLite 数据库文件 |
| `TD_PHOTO_DIR` | `data/photos` | 车身照片本地目录 |
| `TD_SCHEDULER` | `1` | 进程内定时任务开关（每 10 秒） |

其他命令：

```bash
npm test     # 17 个测试：领域规则 + HTTP 集成（node:test）
```

## 页面（车漆白 · 深石墨 · 信号蓝）

- **车辆状态板**：车辆按车型分组为紧凑条目，彩色左边条表示 可预约 / 已锁定 / 试驾中 / 回车检查 / 违章留观 / 待清洁 / 异常封锁；里程数字使用等宽字体。
- **车型日历**：泳道同时展示**车辆占用**（蓝）与**顾问占用**（石墨色），与既有预约冲突的待审单显示为红色。
- **预约审核**：客户代号 + 驾照核验建单；通过即锁定车辆与顾问，押金由付款适配器冻结；跨日单须先有主管单独审批。
- **出车清单**：证件、锁定关系、里程、油量、四方位照片逐项核对；低油量允许出车但留痕。
- **路线计时**：发车即计时，超过路线计划分钟数标红超时。
- **回车对照**：车头/车尾/左/右四个**固定照片位置**，新旧照片之间有**可拖动分隔线**对比；登记新损伤、车辆故障与事故报备。
- **违章留观 / 事故复核 / 清洁**：留观到期由进程内任务自动转入清洁；事故结论仅主管可确认；维修完工由主管解除封锁。

右上角切换操作员（1 名主管 `周衡`、3 名顾问 `林岚/赵北/苏南`）体验数据权限。

## 核心业务规则

### 预约与锁定
- **预约通过后**才锁定车辆与销售顾问；同一车辆不能存在时段重叠的有效预约（建单与审批两道拦截，半开区间，首尾衔接允许）。
- 同一顾问重叠时段只能带一单。
- **跨日试驾必须创建单独审批记录**（仅主管），否则审批拒绝；通过后追加押金。
- **两名顾问同时发车只接受一次**：发车使用 `UPDATE ... WHERE status='approved'` 的 CAS，重复/并发发车被拒。
- **临时换车型**解除车辆与顾问锁定、回到待审核；**同车型改派**保持审核通过并锁定新车；已发车不可换车。

### 出车与回店
- 出车前核对：驾照有效（适配器复核）、里程不小于车辆上次读数、油量、四方位照片齐全。
- 回店补录结束里程，**里程不得倒退**；每次出车/回车写入 `condition_versions`，同车 `seq` 递增形成跨单**里程连续链**。
- 低油量（按车型阈值）出车/回店分别标记；路线超计划时长标记超时。

### 异常与权限
- 回车对照发现新损伤 / 机械故障 / 报备事故 → 车辆置 `blocked`、预约进入 `exception`。
- **普通销售不能清除车况异常，事故结论必须由主管确认**：
  - 主管可判定无责并直接清除（进入留观/清洁），或判定责任成立维持封锁待维修；维修完工后主管执行“解除封锁”。
- **完成违章留观和清洁后车辆才可再次预约**。
- 数据权限：销售只见自己锁定的预约 + 待审核池，且只能操作自己的单；主管可见、可操作全部。

### 定时任务（进程内，每 10 秒）
- 释放迟到超过 15 分钟仍未发车的预约（车辆/顾问解锁、模拟退还押金）。
- 结束已到期的违章留观（车辆自动 `observation → cleaning`）。
- 页面「留观/事故」提供“立即执行一次”按钮（`POST /api/scheduler/tick`）便于演示。

### 模拟适配器（`src/adapters.js`，全虚构）
- **驾照**：`X` 开头无效、`E` 开头过期、`Y` 结尾未成年，其余有效。
- **车机读数**：以车辆最后读数为基准回传里程/油量，允许人工校正。
- **付款**：预约号末位 `9` 返回余额不足，其余冻结成功。

## 主要 HTTP 接口（均以 `X-Staff-Id` 标识操作员）

```
GET  /api/board                         车辆状态板（按车型分组）
GET  /api/calendar?date=YYYY-MM-DD      车辆 + 顾问占用日历
POST /api/customers                     客户代号 + 驾照核验
GET  /api/reservations?view=pending     待审核队列（主管）/ 我的预约
POST /api/reservations                  建预约（含车辆互斥、证件校验）
POST /api/reservations/:id/approve      审核通过（锁车/锁顾问/押金/跨日校验）
POST /api/reservations/:id/reject
POST /api/reservations/:id/overnight    主管创建跨日审批
POST /api/reservations/:id/reassign     同车型改派 / 换车型重审
POST /api/reservations/:id/dispatch     发车（证件/里程/油量/照片，CAS 一次性）
POST /api/reservations/:id/route-end    结束路线计时
POST /api/reservations/:id/return       回店补录里程油量
POST /api/reservations/:id/checkin      回车对照（四方位照片/损伤/故障/事故）
POST /api/reservations/:id/observation  开启违章留观
POST /api/reservations/:id/incident-review  主管事故复核
POST /api/reservations/:id/photos-stub  生成虚构四方位占位照（?kind=before|after&damage=1）
POST /api/photos                        原始字节上传（头：X-Photo-Position/X-Photo-Kind/X-Reservation-Id）
GET  /api/photos/:id/file               读取本地照片文件
POST /api/vehicles/:id/clean            完成清洁上线
POST /api/vehicles/:id/resolve-repair   主管维修完工解除封锁
POST /api/vehicles/:id/clear-condition  权限演示：任何非主管尝试均 403
POST /api/scheduler/tick                立即跑一次定时任务
```

## 存储结构

- SQLite（`src/db.js`）：`reservations` 状态机 + `condition_versions` 车况版本（里程链）+ `photos` 元数据 +
  `overnight_approvals` 跨日审批 + `incident_reviews` 事故复核 + `audit_log` 审计。
- 本地目录 `data/photos/<车辆id>/`：出车前/回店后/事故照片原始文件（演示用为 SVG 占位图）。

## 目录

```
src/
  db.js        SQLite schema（预约/车况版本/照片/跨日/事故/审计）
  adapters.js  驾照核验 / 车机里程油量 / 押金付款 模拟适配器
  service.js   领域规则与状态机（互斥/换车/里程链/权限/留观/事故）
  seed.js      虚构种子数据与四方位占位照片
  app.js       HTTP 路由、照片上传、静态资源
  server.js    启动入口（含进程内定时任务）
public/        原生前端（状态板/日历/审核/出车/计时/对照/留观/复核）
test/          node:test 领域 + HTTP 集成测试
```
